# 直す

1. **まず再現する。** 直す前に、壊れていることを自分の目で 1 回見る。
   再現できないものは直せないし、直ったことも確かめられない。
2. **症状ではなく原因まで降りる。** もっともらしい原因を見つけても、
   **それを消して再現しなくなること**を確かめるまで断定しない。
3. **いちばん小さい変更を当てる。** ついでの整理を混ぜない
   （混ぜると、効いたのがどちらか分からなくなる）。
4. **もう一度、同じ手順で再現を試す。** 通ったら、**全体の試験**も走らせる
   （直した場所だけ見ると、隣を壊したことに気づけない）。
5. 効かなかった手があれば、それも書き残す。次の人の数時間を節約する。

## この現場で実際に外した型

- **数値は分母とセットで読む**（`5,184MHz` を張り付きと読んだが、28,800MHz 中の 1.4 コアだった）。
- **`/health` が 200 でも中身が無事とは限らない。**
- **観測それ自体が対象を壊す**ことがある（並列 SSH が sshd を、前走の残骸が壁を作った）。
- **`ping` が返らない＝停止、ではない。** ICMP だけ落として動いているホストは実在する。
  TCP を開いて確かめる。
