# 出荷する

1. **全体の試験を通す**（一部ではなく全部）。
2. **版を上げる**。版を書く場所が複数あるなら、**全部**（片方だけ上げると、
   中身が名乗る版と出荷の版がずれる）。
3. **出荷の連鎖を通す**。文書のずれ・入口の登録漏れはここで落ちる。
4. **配信ルートを実際に引いて確かめる**。「出したつもり」と「届く」は別物。
5. **入れてみる**。入れた先で、入口が実在することを確かめる
   （エントリポイントの登録漏れは、手元では緑のまま実機だけ壊れる）。

## この現場で実際に壊れた型

- 版ごとの配信 JSON を「既にあるファイル」から作っていたので、
  欠けた版は**二度と埋まらない**。
- 版の比較を**文字列**でやっていて `"0.1.9" > "0.1.71"`＝最新側の穴を 20 版以上見逃した。
- **測る道具が 1 版前の出荷物を測っていた**（ソースを直しても反映されない経路だった）。
